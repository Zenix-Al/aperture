# Build an add-on

An add-on is a separately built userscript selected by a project's `build.addonsManifest`. Reusable source belongs in `addons/<addon>/src/`; a site-specific entry can live under `projects/<project>/`. It uses the shared client bridge/runtime rather than importing the core's live state or starting another core lifecycle.

Two references are available: [generic example entry](../../addons/example-addon/src/main.js) for the full adaptor/application layout, and [Reading Desk bookmark](../../projects/reading-desk/bookmark.js) for a small site-specific implementation. Read the bookmark's imports and lifecycle before adding your own page work.

## Manifest and selection

The selected manifest contains `{"addons": [...]}`. Copy Reading Desk's [manifest](../../projects/reading-desk/addons.manifest.json) and supply your own ID, display metadata, entry/output, version, matches, grants, runtime mode, page scopes and capabilities. Use a unique machine ID and request only the services needed by the add-on.

| Field | Meaning |
| --- | --- |
| `entry` | Repository-relative source module |
| `outfile` | Repository-relative generated userscript path |
| `version` | Independent add-on version |
| `matches` | Explicit manager activation; core-required matches must be contained in the core's matches |
| `pageScopes` | Route keys without the `is` prefix: `isReading` becomes `reading` |
| `runtimeMode`, `requiresCore` | Whether core services are required; the example uses core-required/true |
| `capabilities` | Declared access, e.g. feature, storage, ui.mount, ui.style |

Core discovery is not authorization. Catalog selection, trust, enabled state, scopes, capabilities and request validation govern actions. Client code must handle denied actions or unavailable core and release its owned resources on disable/teardown. Bridge events do not authenticate a script against hostile page code.

## Build and check

```powershell
node scripts/addon-catalog.cjs --config projects/my-site/config.json --check-manifest
node scripts/addon-catalog.cjs --config projects/my-site/config.json --write
npm run build:addons -- --config projects/my-site/config.json --smoke
npm run build:addons -- --config projects/my-site/config.json
```

Install the core and each selected generated add-on script. Building core does not build add-ons. Versions do not bump by default. Catalog outputs are generated by the existing builder; do not hand-edit them.

## Update configuration

Omit `addonUpdates` or set it to `{}` for a bundled local catalog with no remote checks. To enable a remote catalog, set `addonUpdates.catalogURL` in project JSON to the metadata endpoint. Per-add-on manager `updateURL` and `downloadURL` belong in the selected manifest and do not inherit core URLs. Configuring an endpoint does not host files or grant network permissions. See [catalog update contract](../addon-generic/README.md) and [platform API contracts](../addon-platform/README.md).
